## 决策（实施期拍板）

### 1. fake_hermes 改 Python 版（v0.2 bash 版退役路径）
v0.2 fake hermes（v0.2.1 commit 99653ab）是 bash heredoc + PATH 注入 + cygpath 转换,只 Windows 友好。T2a 改 Python 版：
- 跨平台一致（Windows / Linux / macOS 同构）
- argparse 处理参数,无需 bash 变量展开约定
- 替代 v0.2 fake hermes 不冲突；v0.2.1 fake 继续服务于 T4（`tests/test_text_target_e2e.sh`），T2a fake 服务于 v0.3 recipe runner

### 2. recipe prompt_path 用 `$SUBAGENTS_REPO_ROOT` env + 双引号 quote
- env 注入点：`scripts/run_recipe.py` 在调 `subagents.coordinate` 之前 `os.environ["SUBAGENTS_REPO_ROOT"] = REPO_ROOT`（spawn_agent 子 bash 继承父 env → 展开 `$VAR`）
- 双引号 quote 是 **Windows 必需**：REPO_ROOT 含空格（`.../my project/recursive-tune`），无 quote 时 bash 拆词 `python D:/programming/projects/my` → rc=2 file not found（**实施期踩坑 1**）
- YAML 内 quote 写法：`"python \"$SUBAGENTS_REPO_ROOT/scripts/fake_hermes.py\" --profile ..."`

### 3. ratchet 复用 v0.2 git commit 模式,glue 在 T2a 层
- T1 `subagents.coordinate()` 不写 git 细节,接受 `ratchet_fn` 注入（薄骨架纪律）
- T2a `scripts/run_recipe.py` 提供 `git_commit_ratchet()` 默认实现：`git add -A` + `git diff --cached --quiet` 检查 + `git commit -qm`（v0.2 `iter.sh:241-242` 模式复用）
- nothing-to-commit 时跳过 commit 但不报错（cache 命中场景下产物未变是预期；T2a 测试 `test_second_run_no_new_git_commit` 已 verify）

### 4. coverage 算法 cap 在 1.0
- `min(translated_n / original_n, 1.0)`：译文多写也算 100% 覆盖（覆盖 = 原文段落是否被译文"覆盖",不是译文是否"等于"原文）
- 实施期踩坑 2：初版按字面 `trans/orig` 算,翻译含 section 标题导致 ratio=1.25 误判；修后 cap 1.0,coverage pass

### 5. D4 三维不验 fixture 命中（spec D4 占位已明文）
- spec D4：`fixture 不适用 C 类产物,无法构造 ≥10 positive + ≥10 negative ground truth`；T2a 用命令型硬指标替代 D9 fixture 门
- T2a 只验"命令可量化、出数值（pass/fail）",不构造 ground truth
- T2b 真实 e2e 时若有可比 ground truth（D4 OOS 触发条件 = v0.4 撞真实 C 类任务需要跨任务 ground truth）,才形式化 fixture 验证

### 6. cache hit skip spawn（D1 基础版,无 50% 阈值）
- T2a 验：cacheable=true + output 已存在 → status=cached,duration_ms=0,**不 spawn fake_hermes**（`test_second_run_does_not_respawn` 用 monkeypatch 拦截 `subprocess.run` 验证 0 调用）
- T2a **不** 验 wall clock 中位 ≤50% 阈值（spec D1 留 T2b 真实 e2e）；T2a e2e 9 测里 `test_second_run_caches_all_three_agents` 已验 envelopes 全 cached

## 实施期踩坑（避坑笔记）

1. **Windows 路径含空格 → bash -c 必须 quote**：recipe prompt_path 用 `$SUBAGENTS_REPO_ROOT` 时若无双引号,bash 拆词,python 收到截断路径 rc=2。**yaml 写法固定**：所有 `prompt_path` 写 `python \"$SUBAGENTS_REPO_ROOT/...\" ...`。
2. **coverage 段落算法含 section 标题会被算多段**：fake_hermes translator 输出的 "Section intro (translated)" 标题算一段（按空行分）→ 5 段 vs 原文 4 段。算法需 cap 在 1.0,否则判 1.25 → 已修。
3. **git init 时无 user.email/user.name → commit 失败**：run_recipe 自动 `git init` 后需 `git config user.email/name`,否则 commit rc=1。本模块自动 set,无需用户配置。
4. **nothing-to-commit 应跳过 commit 而非报错**：v0.2 `iter.sh:241` 用 `git commit` 失败时会 set -e 退出；T2a 改成先 `git diff --cached --quiet` 检查,有变更才 commit,无变更静默跳过。这与 cache hit 场景一致（产物未变 → 无需新 commit）。
